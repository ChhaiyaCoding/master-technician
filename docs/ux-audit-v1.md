## P0-1 · Photo Diagnosis និង Ask Expert ជា placeholder តែបង្ហាញដូច feature ពិត

**បញ្ហា:**
[src/services/ai.ts](../src/services/ai.ts) មាន `PlaceholderAiProvider` ដែលបញ្ចេញចម្លើយ**សរសេរទុកជាមុន** ជាមួយ `delay(700ms)` ធ្វើពុតជាកំពុងគិត។ `analyzePhotos()` ទទួលតែ `photos.map(p => p.note)` — គឺវា **មិនមើលរូបភាពទាល់តែសោះ**។ `askExpert()` ជា template ឆ្លើយថេរ។ ប៉ុន្តែនៅ [Home.tsx](../src/screens/Home.tsx) ទាំងពីរនេះជា tile ធំស្មើនឹង «ស្វែងរកកូដ DTC» និង «បណ្ណាល័យករណី» ដែលជាទិន្នន័យពិត។

**ហេតុអ្វីជាបញ្ហា:**
នេះមិនមែនបញ្ហារូបរាងទេ — ជាបញ្ហា **ទំនុកចិត្ត**។ ជាងមិនអាចដឹងបានថាផ្នែកណាពិត ផ្នែកណាក្លែង។

**ស្ថានភាពជាក់ស្តែងក្នុងហាង:**
ជាងថតរូប connector ច្រេះមួយ ចុច «វិភាគ» រង់ចាំ ០.៧ វិនាទី ហើយបានចម្លើយ «ពិនិត្យ component ក្នុងរូបរកស្នាមខូច/លេច/ច្រេះ · 50%»។ គាត់គិតថា App បានមើលរូបគាត់មែន។ តាមពិត App ឃើញតែ string ទទេ។ ថ្ងៃណាមួយចម្លើយក្លែងនេះនាំគាត់ប្ដូរគ្រឿងខុស — គាត់នឹងឈប់ជឿ App ទាំងមូល រួមទាំងផ្នែក DTC ដែលពិត។

**ការណែនាំ:** ជ្រើសមួយក្នុងបី៖
- (ក) **លាក់ចោលសិន** — ដកចេញពី Home និង nav រហូតដល់មាន vision AI ពិត (ណែនាំបំផុត — សាមញ្ញ ស្មោះត្រង់)
- (ខ) ដាក់ស្លាក «🚧 កំពុងអភិវឌ្ឍ» ច្បាស់លើ tile និងលើចម្លើយ
- (គ) ប្ដូរ Photo → ជា «ថតរូបភ្ជាប់ទុកក្នុងករណី» (មិនអះអាងវិភាគ) ដែលនេះមានតម្លៃពិតភ្លាមៗ

**អាទិភាព:** P0

## P0-2 · «សកម្មភាពបន្ទាប់ (Next Action)» មិន sticky — បាត់ពេល scroll

**បញ្ហា:**
Sprint 1 ចំណុច #3 គឺ «Next Action must always be visible without scrolling»។ បច្ចុប្បន្ន card នេះគ្រាន់តែដាក់នៅ**ខាងលើ** មិនមែន sticky ទេ (`position: static`)។ ទំព័រវែង 1509px ក្នុង viewport 812px — ពេល scroll ចុះមើល Current Thinking ឬ Evidence នោះប៊ូតុង ✓ OK / ✗ Not OK បាត់អស់។

**ហេតុអ្វីជាបញ្ហា:**
Next Action ជា**ចំណុចសំខាន់តែមួយ**នៃអេក្រង់នេះ។ ការណែនាំ (ខាងលើ) និងការឆ្លើយតប (ខាងលើដែរ) ត្រូវឃើញព្រមគ្នា។

**ស្ថានភាពជាក់ស្តែងក្នុងហាង:**
ជាង scroll ចុះមើលថា «តើទ្រឹស្ដីជំនួសមានអី?» រួចមកវិញភ្លេចថាត្រូវធ្វើតេស្តអី ត្រូវ scroll ឡើងវិញ។ ដៃប្រឡាក់ប្រេង scroll ម្ដងទៀត។ ធ្វើ ១០ ដងក្នុងករណីមួយ។

**ការណែនាំ:** ធ្វើ Next Action ជា **sticky bar នៅបាត** (ដូច «ចាប់ផ្ដើមធ្វើការ» នៅ AI Diagnose ដែលធ្វើបានល្អហើយ) ឬ sticky នៅលើក្បាល។ ណែនាំបាត — មេដៃទៅដល់ងាយ។

**អាទិភាព:** P0

## P1-3 · លេខ % មិនបង្ហាញ — ចំណុចដែលអ្នកចូលចិត្តបំផុត បាត់ទៅវិញ

**បញ្ហា:**
ក្នុងចម្លើយ AI Instant Answer មាន `ConfidenceBar` (របារ) និងស្លាក «ខ្ពស់ / មធ្យម» ប៉ុន្តែ **គ្មានលេខ % ណាមួយបង្ហាញលើអេក្រង់ទេ** (ពិនិត្យរួច៖ `/\d+\s?%/` រកមិនឃើញក្នុង body ទាំងមូល)។ ទិន្នន័យ `c.confidence` មានស្រាប់ គ្រាន់តែមិន render។

**ហេតុអ្វីជាបញ្ហា:**
អ្នកបាននិយាយច្បាស់ថា៖ *«ខ្ញុំចូលចិត្ត App ត្រង់ ពេលយើងវាយ DTC Code ចូល វាលោតថាអាចខូចអី ជា% ពិតជាល្អ»*។ បច្ចុប្បន្នមានតែរបារ ដែលអានលឿនមិនបាន — «ខ្ពស់» បី មិនប្រាប់ថាមួយណាខ្ពស់ជាង។

**ស្ថានភាពជាក់ស្តែងក្នុងហាង:**
Spark plug, Ignition coil, Injector — ទាំងបីស្លាក «ខ្ពស់» ដូចគ្នា។ ជាងសួរ «ចាប់ពីមួយណាមុន?» App មិនឆ្លើយ។ បើឃើញ 82% / 74% / 58% គាត់ដឹងភ្លាម។

**ការណែនាំ:** បង្ហាញលេខ `{c.confidence}%` ជាអក្សរដិត នៅជាប់ចំណងជើងមូលហេតុ។

**អាទិភាព:** P1

## P1-4 · ត្រូវជ្រើសម៉ាករថយន្តជាមុន ទើបចាប់ផ្ដើមធ្វើការបាន + ប៊ូតុង disabled មើលមិនដាច់

**បញ្ហា:**
`canStart = brand.trim() && problem.trim()`។ បើគ្មានម៉ាក ប៊ូតុង «ចាប់ផ្ដើមធ្វើការ» disabled ប៉ុន្តែនៅតែ**ពណ៌ទឹកក្រូចពេញ** (`opacity: 0.5`, background `rgb(249,115,22)`) — មើលទៅដូចប៊ូតុងធម្មតា។ ចុចទៅគ្មានអ្វីកើតឡើង។

**ហេតុអ្វីជាបញ្ហា:**
ពីរបញ្ហាជាន់គ្នា៖ (១) ទាមទារព័ត៌មានដែល engine មិនចាំបាច់ ផ្ទុយនឹងគោលដៅ «មិនចង់មានច្រើនដំណាក់កាល» (២) ប៊ូតុងស្លាប់ដែលមើលទៅរស់ = ការឆាប់ខឹង។

**ស្ថានភាពជាក់ស្តែងក្នុងហាង:**
ជាងវាយ P0301 ឃើញចម្លើយល្អ ចង់ចាប់ផ្ដើមធ្វើការ ចុចប៊ូតុងធំ — គ្មានអ្វីកើត។ ចុចម្ដងទៀត។ ចុចខ្លាំង។ បន្ទាត់តូចពណ៌ប្រផេះ «ត្រូវការត្រឹម៖ ម៉ាករថយន្ត + បញ្ហា» នៅក្រោមប៊ូតុង គាត់មិនអាន។

**ការណែនាំ:**
- ធ្វើ disabled ឲ្យមើលដាច់ច្បាស់ (ប្រផេះ គ្មានពណ៌ទឹកក្រូច)
- បើ disabled ហើយចុច → scroll ឡើងទៅ field ដែលខ្វះ ហើយបំភ្លឺវា
- ពិចារណា៖ អនុញ្ញាតឲ្យចាប់ផ្ដើមដោយ**គ្មានម៉ាក** ក៏បាន (ដាក់ជា «មិនបញ្ជាក់») ព្រោះ engine ដំណើរការបានស្រាប់

**អាទិភាព:** P1
