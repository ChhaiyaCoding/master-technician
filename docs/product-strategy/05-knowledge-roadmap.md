# 05 — Knowledge Roadmap

Master Technician's long-term moat is **knowledge depth**. Reference data alone is
a commodity (ALLDATA/Autodata have it); our advantage is **structured knowledge +
the shop's own real repairs + AI that reasons over both**, delivered Khmer-first on
mobile.

This roadmap layers knowledge from shallow to deep. **Each level makes the
diagnosis loop (`03`) more accurate and the AI (`ai-system.md`) less likely to
guess.** Levels roughly build on each other but can be developed in parallel where
data is available.

**Status legend:** ✅ built · 🔜 near-term · 🌐 future.
**Content types:** *reference* (authored/licensed data) vs *earned* (generated by
technicians using the app).

---

## Level 1 — Vehicle Information  ✅ *reference*
- **What:** brands, models, years, engines, transmissions; per-model system maps.
- **Today:** curated brands/models/engines with free-text fallback.
- **Next:** broader coverage; VIN/plate decode to auto-fill; per-model common-fault
  profiles.
- **Why it matters:** everything else is scoped by *which vehicle*. Better vehicle
  data sharpens every downstream layer.

## Level 2 — DTC (Diagnostic Trouble Codes)  ✅ *reference*
- **What:** code meaning, related systems, possible causes, inspection flow, common
  mistakes, severity (P/C/B/U codes incl. HV/SRS).
- **Today:** a 12-entry knowledge base with full structure.
- **Next:** expand coverage; manufacturer-specific/enhanced codes; sub-code
  handling (e.g. P0700 → read TCM sub-codes).
- **Why:** a code is the entry point to diagnosis; interpreting it in context is
  our first clear win over scan-tool apps.

## Level 3 — Inspection Flows  ✅ *reference*
- **What:** ordered "what to check, in what order, how" — cheapest/fastest
  confirming test first; confirm-before-replace.
- **Today:** inspection flows in DTC pages and diagnosis results.
- **Next:** interactive checklists that record pass/fail and branch on results.
- **Why:** turns a code into *action*; prevents parts-cannon repairs.

## Level 4 — Repair Procedures  🌐 *reference*
- **What:** step-by-step repair/replacement procedures per component/model.
- **Plan:** author/curate common procedures; surface inline at the "Repair" step;
  link from causes and DTCs.
- **Why:** closes the loop from *what's wrong* to *how to fix it* — moves MT from
  diagnosis assistant to a fast, end-to-end repair reference.

## Level 5 — Wiring Diagrams  🌐 *reference*
- **What:** circuit diagrams, connector/pinout info, component locations.
- **Plan:** mobile-friendly, zoomable diagrams tied to systems/DTCs; especially for
  electrical/network faults (persona P4).
- **Why:** essential for electrical diagnosis; a major reason techs still open a
  laptop today. Bringing it to mobile is high-value.

## Level 6 — Torque Specifications & Measured Values  🌐 *reference*
- **What:** torque specs, fluid capacities/types, and **known-good measured values**
  (voltages, pressures, resistances, live-data ranges).
- **Plan:** quick lookups at the "Measure" and "Repair" steps ("what should this
  read?"); attach actual readings to cases.
- **Why:** correct assembly + a baseline to compare measurements against — this is
  where good techs confirm root cause.

## Level 7 — Technical Service Bulletins (TSBs)  🌐 *reference*
- **What:** manufacturer bulletins on known issues, updated procedures, recalls.
- **Plan:** surface relevant TSBs by vehicle + symptom/DTC.
- **Why:** many "hard" faults are known issues with a documented fix; TSBs prevent
  wasted diagnosis time.

## Level 8 — Known Failures (Failure Patterns)  🌐 *earned + reference*
- **What:** common failure patterns per model/system ("this engine at this mileage
  commonly fails here"), from aggregated cases + curated data.
- **Plan:** derive from the growing case library + TSBs + expert curation; show as
  "commonly seen on this vehicle."
- **Why:** encodes tribal knowledge; dramatically narrows the cause list up front.
  Bridge between reference data and earned data.

## Level 9 — Real Repair Cases  ✅ *earned*
- **What:** technicians' actual solved cases — symptom, DTCs, root cause, repair,
  parts, notes, photos; searchable, with **similar-case** matching.
- **Today:** local case library + similar cases.
- **Next:** team/shared library, cloud sync, community (opt-in, moderated,
  anonymized).
- **Why:** **the flywheel.** Every job makes the system smarter and is unique to MT —
  no reference vendor has your shop's history. This is the defensible core.

## Level 10 — AI Learning System  🌐 *earned + reference, synthesized*
- **What:** AI that reasons over **all layers** — vehicle + DTC + flows + procedures
  + wiring + specs + TSBs + known failures + real cases — to produce ranked,
  evidence-backed, safe diagnoses, and that **improves as more cases accumulate**.
- **Plan:** retrieval-grounded real AI (roadmap Phase 3+), continually enriched by
  Levels 1–9; strictly obeys `ai-system.md` (no guessing, ask follow-ups, rank,
  inspection steps, evidence, safety).
- **Why:** the payoff of the whole pyramid — knowledge that compounds into an
  assistant that gets measurably better over time.

```
              L10       │   AI Learning System       │  synthesizes everything below
                        ├───────────────────────────┤
              L9        │   Real Repair Cases   ✅   │  ← the flywheel (earned, unique)
              L8        │   Known Failures           │
              L7        │   Technical Service Bulls. │
              L6        │   Torque + Measured Values │
              L5        │   Wiring Diagrams          │
              L4        │   Repair Procedures        │
              L3        │   Inspection Flows    ✅   │
              L2        │   DTC                 ✅   │
              L1        │   Vehicle Information  ✅  │  ← foundation
                        └───────────────────────────┘
```

## Guiding principles

- **Structure over dumps.** Every level is typed and queryable (extends
  `database-schema.md`), never a PDF blob — so AI and search can use it.
- **Earned data is the moat.** L9 real cases and L8 patterns are ours alone; invest
  in making capture effortless (see `03` step 10).
- **Localize.** Knowledge is Khmer-first; English technical terms preserved.
- **Ground the AI.** L10 must *cite* L1–L9 as evidence, never invent.
- **Respect licensing.** Reference layers (L4–L7) may require partnerships/licensing;
  plan for sourcing, not scraping.
