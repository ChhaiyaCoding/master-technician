# UX Blueprint — Master Technician

The complete user-experience design, produced **before** further implementation.
Design only — no code, no components. It grounds the intended experience in the
screens that exist today (✅) and marks what is planned (🔜) or future (🌐).

| Doc | What it defines |
| --- | --- |
| [01-app-map.md](01-app-map.md) | Every screen and the navigation hierarchy; how the example flow maps onto the app |
| [02-user-flow.md](02-user-flow.md) | Complete task flows (Diagnose, DTC, Photo, Repair Case, Ask Expert, Resume), screen by screen |
| [03-screen-specifications.md](03-screen-specifications.md) | Each screen: purpose, primary/secondary actions, inputs, outputs, navigation, empty/loading/error |
| [04-navigation-system.md](04-navigation-system.md) | Navigation philosophy: bottom nav, back behavior, deep links, recent items, continue previous work, search |
| [05-information-architecture.md](05-information-architecture.md) | The information spine (Vehicle → … → Repair Case) and how information is prioritized |
| [06-interaction-principles.md](06-interaction-principles.md) | Interaction rules: one-hand, large targets, minimal typing, fast search, offline-first, minimal screen time / maximum repair time |

**North star for all of it:** *reduce searching time, not screen time* — open → find
in seconds → close → keep repairing. See
[../MASTER-TECHNICIAN-BIBLE.md](../MASTER-TECHNICIAN-BIBLE.md) and
[../product-strategy/design-principles.md](../product-strategy/design-principles.md).

> This is the blueprint. Implementation sequencing lives in
> [../roadmap.md](../roadmap.md); nothing here is built beyond what's marked ✅.
